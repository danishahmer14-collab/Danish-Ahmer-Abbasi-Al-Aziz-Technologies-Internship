## What I Did
Firstly, I set up a Python virtual environment and installed torch and matplotlib using pip. I then wrote Tasksw3d2.py, a script that builds and trains a neural network in PyTorch. For the data, I generated a small synthetic 2-class "two moons" dataset (400 samples, 2 features) using NumPy, wrapped it in a custom Dataset class, and split it into training (80%) and validation (20%) sets with random_split. I loaded the data in batches of 16 using DataLoader, with shuffling enabled for training. Next, I defined a SimpleNet model by subclassing nn.Module, giving it two hidden layers (16 units each) with ReLU activations and an output layer with 2 logits. I used nn.CrossEntropyLoss as the loss function and torch.optim.Adam (learning rate 0.01) as the optimizer. I then wrote a training loop (forward pass → loss.backward() → optimizer.step() → optimizer.zero_grad()) and a separate validation loop (model.eval() + torch.no_grad()) that ran after every epoch. I trained the model for 50 epochs, tracking training loss, validation loss, and validation accuracy each epoch. Afterward, I saved the trained model's weights with torch.save(model.state_dict(), "simple_net.pt") and reloaded them into a fresh model instance with load_state_dict() to confirm the save/load process worked correctly. Finally, I plotted the training and validation loss curves along with the model's learned decision boundary, saving the plot as pytorch_training_curves.png. Running the script end-to-end, the final validation accuracy reached ~97.5%

## Key Learnings
PyTorch tensors are similar to NumPy arrays, except they can compute gradients automatically (autograd) and can be moved to a GPU using .to(device) for faster computation. Since I don't have a GPU set up yet, everything was done on the CPU, which was still fast enough for this small dataset. Splitting data handling into two parts—using Dataset to define how to get a single sample and DataLoader to automatically batch and shuffle the samples—makes the training loop much cleaner. The standard way to define a model is by subclassing nn.Module, where the layers are defined in __init__() and the actual computation is handled in forward(). Unlike Day 1, I didn't have to write backpropagation by hand; gradients are automatically computed by loss.backward(), and the optimizer applies the updates. This significantly shortened the code compared to the from-scratch NumPy version. Even for the simplest models, it is important to distinguish between model.train() and model.eval(), as some layers (like dropout or batch norm) behave differently during training and inference, so I'm making a habit of setting the correct mode before each loop. Additionally, a validation loop uses torch.no_grad() to prevent gradient tracking; this is necessary because we are only evaluating the model's performance on unseen data, not updating weights. Saving models using state_dict() (rather than the entire model object) is the recommended approach because it is more portable and only saves the learned weights, not the full class definition. Finally, seeing the decision boundary plot made the concept of a "non-linear" classifier click for me: a single straight line couldn't separate the two moon-shaped classes, but the trained network learned to curve its boundary around them.
